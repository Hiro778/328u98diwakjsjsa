==================================================
PHASE 1 — ADMIN PAYMENT DATA MODEL
==================================================

Create an admin read-only payment monitoring layer.

Prefer centralized SECURITY DEFINER RPCs rather than exposing broad raw-table access.

Potential RPC structure:

public.get_admin_payments(
  p_payment_type,
  p_search,
  p_payment_provider,
  p_payment_method,
  p_payment_status,
  p_transaction_status,
  p_date_from,
  p_date_to,
  p_sort,
  p_limit,
  p_offset
)

and:

public.get_admin_payment_detail(p_payment_id, p_payment_type)

Only create parameters/fields that are actually compatible with the audited schema.

RPC requirements:

- SECURITY DEFINER
- SET search_path = ''
- fully qualified table names
- caller authorization through public.is_admin()
- unauthorized caller → 42501
- revoke EXECUTE from PUBLIC
- revoke EXECUTE from anon
- grant authenticated only as appropriate
- no service-role key in frontend
- no raw SQL from browser

==================================================

Stage 8 is PAYMENT MONITORING.

Do NOT add:
