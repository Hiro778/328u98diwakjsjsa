Implementasikan redesign "Laporkan Bug" menjadi native Bug Report Form di dalam aplikasi BisnisSehat.

FLOW:
Customer Support
→ klik "Laporkan Bug"
→ buka modal/page "Laporkan Bug"
→ user mengisi form
→ submit
→ ticket masuk ke Admin Support (/admin/support)

FIELD FORM:

1. Nama
   - OPTIONAL
   - text input
   - jika kosong tetap boleh submit
   - jangan gunakan ini sebagai identity/authentication

2. Deskripsi Bug
   - WAJIB
   - textarea
   - tidak boleh submit jika kosong
   - trim whitespace
   - berikan validation message yang jelas

3. Foto / Screenshot
   - WAJIB
   - hanya image
   - accept: image/png, image/jpeg, image/webp
   - validasi ukuran file sebelum upload
   - tampilkan preview gambar
   - user harus memilih screenshot/foto sebelum submit
   - tidak boleh submit jika screenshot belum ada

IDENTITAS:
- user_id WAJIB berasal dari authenticated Supabase session.
- Jangan meminta user memasukkan user_id/email untuk ticket ownership.
- business_id gunakan business context/order context yang memang sudah authenticated dan tervalidasi.
- Jangan menerima arbitrary user_id/business_id dari input form.

DATABASE:
Gunakan EXISTING public.support_tickets.
Jangan membuat tabel support ticket baru.

Mapping:
- user_id = authenticated user
- business_id = verified current business jika tersedia
- subject = "Bug Report" atau subject yang sesuai
- category = "Bug"
- description = isi deskripsi user
- page_url = window.location.pathname + window.location.search
- screenshot_url = uploaded screenshot
- priority = "medium"
- status = "new"
- admin_note = NULL

UPLOAD:
1. Audit Storage bucket yang sudah ada terlebih dahulu.
2. Jika ada bucket yang cocok untuk support screenshot, gunakan bucket tersebut.
3. Jika belum ada, buat bucket khusus support screenshot.
4. Jangan gunakan service_role key di frontend.
5. Storage path harus tenant/user scoped, contoh:
   support/{user_id}/{ticket_id}/{filename}
6. Validasi MIME type dan ukuran file.
7. Jangan memperbolehkan user menentukan path arbitrer.
8. User hanya boleh upload/access screenshot milik ticket mereka.
9. Admin Support tetap dapat membaca screenshot ticket.
10. Jangan membuat bucket public jika tidak diperlukan.

SUBMIT:
- Upload screenshot terlebih dahulu setelah ticket ID tersedia.
- Kemudian simpan screenshot_url ke support_tickets.
- Jika upload gagal → ticket jangan dianggap berhasil terkirim.
- Jika database insert/update gagal → jangan menampilkan success palsu.
- Handle cleanup jika upload berhasil tetapi ticket persistence gagal.

ADMIN SUPPORT:
Ticket yang dibuat harus langsung muncul di:
`/admin/support`

Category:
`Bug`

Status awal:
`new`

Admin tetap bisa:
- melihat detail
- melihat screenshot
- mengubah status
- mengubah priority
- menambahkan admin note
- melakukan action yang memang sudah tersedia di Admin Support

JANGAN mengubah existing support workflow yang sudah bekerja.

SECURITY:
- User A tidak boleh membaca screenshot/ticket User B.
- User tidak boleh mengubah status ticket sendiri.
- User tidak boleh menentukan admin_note.
- User tidak boleh menentukan user_id.
- User tidak boleh menentukan arbitrary business_id.
- User tidak boleh menghapus ticket.
- Admin authorization tetap server-side.
- Jangan expose service_role/Midtrans/JWT secret ke frontend/dist.

TEST WAJIB:

1. Form bisa dibuka dari Customer Support → Laporkan Bug.
2. Nama kosong → submit tetap valid.
3. Deskripsi kosong → submit ditolak.
4. Screenshot kosong → submit ditolak.
5. File non-image → ditolak.
6. File terlalu besar → ditolak.
7. Image valid → preview muncul.
8. Submit valid → ticket masuk public.support_tickets.
9. Ticket memiliki user_id authenticated yang benar.
10. Category = Bug.
11. Status = new.
12. Screenshot tersimpan dan bisa dibaca oleh Admin Support.
13. User A tidak bisa membaca screenshot/ticket User B.
14. Double click submit tidak membuat duplicate ticket.
15. Upload failure ditangani tanpa success palsu.
16. Database failure setelah upload melakukan cleanup jika memungkinkan.
17. Admin Support menampilkan ticket baru.
18. Existing support tests tetap PASS.
